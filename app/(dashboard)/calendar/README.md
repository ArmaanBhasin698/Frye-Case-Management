# app/(dashboard)/calendar

Firm calendar. `page.tsx` renders month / week / day / agenda views over the
existing `CalendarEvent` model (recurrence expanded at read time, with
per-occurrence exceptions applied) plus matter `Deadline`s as all-day items,
via `lib/calendar/queries.ts#getCalendarItems`. `?tasks=1` adds a read-only
layer of task due dates built from existing `Task` rows (matter-scoped like
the Tasks page; the staff filter means assignee) — tasks are never copied
into `CalendarEvent`. View, date, and filters live in the URL
(`?view=week&date=2026-10-23&matterId=…&tasks=1`).

- `events/new` — create (optionally `?matterId=` pre-linked, `?date=`, and
  `?contactId=` — "Schedule with this contact": prefilled only if the user
  can see the contact; a matter is preselected only when exactly one of the
  user's matters links that contact).
- `events/[eventId]` — detail with Join / Copy meeting-link actions and
  cancel. For a repeating event, `?occurrence=<original start ISO>` shows
  one occurrence with "Edit this occurrence", "Cancel this occurrence",
  "Restore to series", and "Edit entire series".
- `events/[eventId]/occurrence?start=<original start ISO>` — edit one
  occurrence (time, title, location, link; blank fields keep the series
  value; at most 31 days from its original start).
- `events/[eventId]/edit` — edit the entire event or series. Existing
  occurrence exceptions are kept when their original start is still an
  occurrence of the edited series; orphaned ones are removed in the same
  transaction (counts audited).

Occurrence identity (also the anchor for any future calendar sync): event id
+ the occurrence's *original* UTC start as generated by the series rule
(iCalendar RECURRENCE-ID semantics), stored as
`CalendarEventException(eventId, originalStart)` — unique. A moved occurrence
keeps its original identity. Forged instants that the rule doesn't generate
are rejected like unknown ids. See `lib/calendar/occurrences.ts`.

Reminders: `reminderMinutesBefore` (primary) plus
`reminderOffsetsMinutes` (additional) — in-app only; the dashboard reminder
window opens at the largest offset. Cancelled occurrences never remind and
moved occurrences remind relative to their new start.

Authorization: `lib/calendar/access.ts` — matter-linked events follow matter
access; matterless (internal) events are visible to ADMIN, their creator, and
their staff attendees. Every write (including per-occurrence edits) re-checks
this plus matter, attendee, and contact ids server-side
(`lib/calendar/actions.ts`). Times are stored in UTC with the event's IANA
zone; the grid renders in `FIRM_TIME_ZONE` (America/New_York). Meeting links
are user-entered, https-only, never created through a provider API.
